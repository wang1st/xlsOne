# xlsOne 脚本管理指南

> 最近更新：2026-07-16

本文档用于约束项目脚本入口，避免构建、打包、部署脚本散落在根目录或保留多个旧入口。

## 目录分工

| 目录 | 职责 | 规则 |
|------|------|------|
| `scripts/` | 仓库级入口：Swift/macOS、站点部署、跨平台包装器 | 可被 README 和 runbook 直接引用 |
| `scripts/deploy/` | 站点与安装包部署 | 只保留当前可用的一键部署入口 |
| `cpp/scripts/` | Qt/C++ 构建、打包、验证 | 只放 C++/Qt 子项目需要的脚本 |
| `activation/domestic-server/deploy/` | 国内激活服务部署 | 只放服务器部署配置与上传工具 |
| `.build/` | 本地缓存和发版收口目录 | 不提交到 git |

根目录不再新增脚本。原来的 `run-app.sh` 已移除，使用 `scripts/build_and_open_app.sh`。

## 打包脚本命名规则

所有打包脚本统一使用：

```text
package_<platform>_<artifact>[_flavor].<ext>
```

规则：

- 必须以 `package_` 开头，不再使用 `build_*` 表示打包。
- `<platform>` 使用 `windows`、`macos`、`linux`。
- `<artifact>` 使用真实产物类型，例如 `msi_zip`、`dmg`、`deb`。
- 需要区分实现口味时加 `qt`、`swift`、`cpack` 等后缀。
- shell 文件统一用下划线，不使用连字符。

## 发版产物管理

构建缓存和发版产物分开：

- `cpp/build-*`：各平台构建缓存，可删除重建。
- `cpp/xlsOne-<version>-macos-universal.dmg`：Qt DMG 本地验包位置。
- `.build/release-artifacts/<version>/`：唯一发版收口目录，`scripts/deploy/deploy.sh` 会把待上传的 `.deb`、`.msi`、`.zip`、`.dmg` 复制到这里，再计算 checksum 和上传。

`scripts/deploy/deploy.sh` 找不到 Linux 包时，会调用 `cpp/scripts/package_linux_deb.sh --bundle`。该脚本按当前 Linux 主机架构出包：`x86_64` 生成 `linux-amd64`，`aarch64/arm64` 生成 `linux-arm64`；macOS 上不会直接构建 `.deb`，需要先在 Linux 构建机打好包再上传。

上传前只检查：

```bash
ls -lh .build/release-artifacts/<version>/
```

## 新增脚本规则

新增脚本前先确认是否可以扩展现有入口。确需新增时：

1. 放到职责匹配的目录，不放根目录。
2. 打包脚本必须遵守 `package_<platform>_<artifact>[_flavor].<ext>`；非打包脚本也要体现动作和对象，例如 `validate_deb.sh`。
3. 顶部写清用途、用法、关键环境变量。
4. 在 `scripts/README.md` 和本指南登记。
5. 如果替代旧脚本，同时更新 README、runbook 和 `rg` 能搜到的文档引用。
6. 对 shell 脚本至少运行 `bash -n`；对 PowerShell 脚本至少检查 `#requires`、参数和引用路径。
