# Windows 版本授权、程序加密与收款方案（国内）

> 讨论稿 · 2026-06-29  
> 前提：Linux 版本持续免费；Windows 版本考虑商业化；尽量使用开源方案；作者为独立开发者，暂无公司。

---

## 1. 目标与约束

| 维度 | 要求 |
|------|------|
| 平台策略 | Linux 永久免费；Windows 付费（可保留有限试用） |
| 技术栈 | 优先开源、可自托管、低运维成本 |
| 收款 | 国内可用，支持个人身份，无需营业执照 |
| 安全 | 授权可校验、可设备绑定、有一定反篡改能力；接受“防君子不防小人” |
| 体验 | 激活流程尽量简单，支持离线使用 |

---

## 2. 授权模式建议

推荐 **“永久买断 + 设备绑定 + 14 天试用”** 模式：

- **试用**：安装后自动开始 14 天全功能试用，无需注册。
- **购买**：一次付费，永久使用当前主版本（如 1.x）。
- **激活**：输入许可证密钥后绑定当前设备；支持每年有限次数换机（如 3 次/年）。
- **大版本升级**：2.x 可另行定价或提供优惠升级，旧版本仍可继续使用。

不强制订阅，降低国内用户付费心理门槛，也减少独立开发者后续的订阅服务运维负担。

## 3. 技术方案：授权与加密

### 3.1 许可证格式

采用 **Ed25519 数字签名** 的许可证文件（或短密钥 + 在线换取签名文件）。

- **生成端（服务器）**：用 Ed25519 私钥对许可证内容签名。
- **客户端（Windows）**：内置公钥，验证签名；不联网也能校验。

开源库选择：

- C++：`libsodium`（跨平台，Ed25519 支持成熟）
- 备选：OpenSSL 3.x（也支持 Ed25519）

> 参考：libsodium 是广泛使用的现代密码学库，许可证为 ISC，可商用。

### 3.2 许可证内容

```json
{
  "key_id": "ABCD-EFGH-IJKL",
  "plan": "lifetime",
  "device_hash": "sha256-of-fingerprint",
  "issued_at": 1719830400,
  "expires_at": 0,
  "signature": "base64-ed25519-signature"
}
```

- `device_hash` 可为空，表示未绑定设备；首次激活时写入当前设备指纹。
- `expires_at = 0` 表示永久授权。

### 3.3 设备指纹

Windows 上采集以下信息的组合哈希：

- 主板序列号（`WMIC BASEBOARD GET SerialNumber`）
- CPU ID（`WMIC CPU GET ProcessorId`）
- 系统盘序列号（`WMIC DISKDRIVE GET SerialNumber`）
- 机器 GUID（注册表 `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid`）

策略：

- 取 2~3 项组合生成稳定指纹。
- 允许小范围变动（如换硬盘后 2/3 匹配即视为同一台机器）。
- 明确限制每年迁移次数，防止密钥公开滥用。

### 3.4 激活流程

```
用户购买 → 收到许可证密钥
     ↓
在 Windows 客户端输入密钥
     ↓
客户端生成设备指纹 → 连同密钥一起请求激活 API
     ↓
服务端校验密钥有效性 → 生成带签名的许可证文件
     ↓
客户端本地保存许可证，后续启动离线校验
```

离线 fallback：

- 若用户无法联网，可在另一台能联网的设备上通过网页激活页面输入密钥 + 手动上传设备指纹文件，下载 `.license` 文件后导入 Windows 客户端。

### 3.5 程序保护（现实可行的部分）

完全防止逆向几乎不可能，也无需追求“不可破解”。建议以下低成本、开源或原生手段：

| 措施 | 方案 | 说明 |
|------|------|------|
| 授权校验 | libsodium Ed25519 | 核心防线，密钥无法伪造 |
| 代码混淆 | 编译器优化 + strip 符号表 | 增加静态分析难度 |
| 反调试（轻度） | 定时检测调试器/VM | 可作为提示，不建议过度依赖 |
| 打包压缩 | UPX（可选） | 减小体积，但可被脱壳，仅作轻度保护 |
| 代码签名 | 个人代码签名证书 | 消除 SmartScreen 拦截，提升可信度；可选，年费约几百元 |

不推荐：

- 依赖闭源壳/加壳工具：授权不透明，可能引入兼容性与安全风险。
- 过度反调试：影响稳定性，且仍会被绕过。

### 3.6 与现有激活服务的整合

项目已有 Cloudflare Worker（`activation/worker/src/index.ts`）处理激活与 Lemon Squeezy 回调。

建议：

- 保留 Worker 作为统一激活服务端。
- 新增 `/api/activate/windows` 与 `/api/license/download` 端点。
- Worker 使用 Ed25519 私钥签名许可证，公钥嵌入 Windows 客户端。
- 国内用户访问 Cloudflare 可能不稳定，可配置 Aliyun/腾讯云函数作为 fallback（与现有 `API.fallback` 设计一致）。

## 4. 收款方案（国内，无公司）

### 4.1 方案对比

| 方案 | 是否需要营业执照 | 是否自动回调 | 手续费 | 资金到账 | 风险/说明 |
|------|------------------|--------------|--------|----------|-----------|
| 个人微信/支付宝收款码 | 否 | 否 | 无 | 即时到个人账户 | 异地收款易风控；需人工核对发货 |
| 爱发电（afdian.net） | 否 | 是（Webhook/API） | 约 6% | 到个人账户 | 创作者平台，适合个人；可自动发货 |
| 第三方服务商（YunGouOS / 虎皮椒 / Zpay 等） | 否 | 是 | 开户费 + 每笔 1%~3% 不等 | 官方结算到个人银行卡 | 平台稳定性参差不齐，需仔细甄别 |
| 微信/支付宝官方商户 | 需要公司或个体户 | 是 | 0.38%~0.6% | 对公/对私账户 | 最稳定，但注册成本较高 |
| 出海收款（Gumroad / Lemon Squeezy / Paddle） | 否 | 是 | 较高（5%+） | 外币/ PayPal | 国内用户支付不便，适合海外市场 |

### 4.2 分阶段推荐

#### 阶段一：验证需求（推荐立即采用）

**爱发电 + Webhook 自动发货**

- 注册爱发电创作者账号，创建“表表归一 Windows 版”商品/方案。
- 定价建议：¥29~¥68（一次性），低于企业软件，符合个人工具定位。
- 在爱发电后台配置 Webhook URL，指向现有 Cloudflare Worker 的新端点。
- 用户付款后，Worker 自动生成密钥并通过爱发电私信/邮件返回。

优点：

- 个人可直接收款，无需营业执照。
- 支持微信、支付宝，用户体验好。
- Webhook 可做到自动发货，无需人工值守。

缺点：

- 平台抽成约 6%。
- 被爱发电品类/风控政策约束。

#### 阶段二：规模化后

若月销量稳定超过一定规模（例如月均 ¥3000+），可考虑：

1. 注册**个体工商户**（成本低，很多地区可线上办理）。
2. 申请微信/支付宝官方商户号，费率最低、最稳定。
3. 自建支付收银台，用户直接在官网完成支付并自动激活。

不建议一开始就走这条路：注册、记账、报税都有持续成本，业务未验证前不要过早重投入。

### 4.3 自动发货流程（爱发电 + Worker）

```
用户点击购买 → 跳转爱发电支付页
     ↓
爱发电收款成功 → 调用 Cloudflare Worker /api/webhook/afdian
     ↓
Worker 校验签名 → 在 D1 数据库记录订单
     ↓
Worker 生成唯一许可证密钥 → 调用爱发电 API 发送私信给用户
     ↓
用户在 Windows 客户端输入密钥完成激活
```

所需新增组件：

- `POST /api/webhook/afdian`：接收爱发电订单回调。
- `POST /api/activate/windows`：校验密钥 + 设备指纹，返回签名许可证。
- D1 表：`windows_keys`（key, order_id, plan, used, device_hash, created_at）。
- 爱发电私信发送：使用其 `/api/open/send-msg` 接口。

## 5. 法律与税务提示（非专业建议）

- **收入纳税**：个人取得的软件销售收入属于个人所得税“经营所得”或“劳务报酬”，建议通过个税 APP 或电子税务局自行申报。
- **发票**：如需给用户开票，个人可通过电子税务局申请“自然人代开发票”。
- **ICP 备案**：网站已完成备案；若未来接入官方支付，通常要求网站备案主体与商户主体一致。
- **用户协议 / 隐私政策**：Windows 付费版应在安装或首次启动时展示《最终用户许可协议（EULA）》，明确授权范围、禁止反编译、退款政策等。

建议后续咨询专业税务/法律顾问。
