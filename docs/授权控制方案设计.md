# 表表归一 授权控制方案设计（简化版）

> 编写时间：2026-07-10
> 修订：2026-07-10 — 去掉 Webhook，纯靠「预生成 + 爱发电卡密池 + 激活时验证」
> 目标：年度授权 + 激活次数控制 + 批量预生成池化分发，系统最简、最可靠。

---

## 一、现状分析

### 已有能力（代码已实现）

| 能力 | 当前实现 | 位置 |
|------|---------|------|
| 时间控制 | `expires_at` 字段（Unix 秒，0=永久） | `license_manager.cpp:348-354` 客户端检查；`buildWindowsLicense()` 服务端签发 |
| 设备绑定 | 设备指纹（主板+CPU+硬盘+MachineGuid 组合 SHA256） | `license_manager.cpp` `deviceFingerprint()` |
| 换机迁移 | 每年 3 次（365 天滚动窗口） | `issueWindowsLicense()` 服务端检查 |
| 批量生成 | Admin API `generate-windows-keys` | `server.js:508` / `index.ts:870` |
| 离线激活 | 网页下载 .license 文件 → 客户端导入验签 | `/api/license/download` + `applyLicenseFile()` |
| 14 天试用 | 全功能试用，本地 QSettings 计时 | `kTrialDurationDays = 14` |

### 现有问题（需要改造）

| 问题 | 说明 |
|------|------|
| **过期状态缺失** | `LicenseState::Expired` 枚举存在但 `loadPersistedState()` 从未设置它——过期时直接清 license → 回退到 Unactivated，用户看不到「已过期」提示 |
| **换机限制是"每年3次"** | 用户要的是「总共3次，用完作废」，不是每年重置 |
| **无激活计数** | 没有 `activation_count` 字段，无法区分「同机重装」（不应计数）和「换机」（应计数）|
| **爱发电只发终身码** | `plan = 'personal_lifetime'` 硬编码，不支持年度版 |
| **过期无引导** | 过期后用户不知道该去买新码，只看到「未激活」 |
| **Webhook 依赖** | 当前发码依赖 webhook 在线，服务器挂了就发不了码 |

## 二、授权模型设计

### 2.1 套餐体系

| 套餐 | plan 值 | 有效期 | 激活次数 | 适用场景 |
|------|---------|--------|---------|---------|
| 年度版（主力） | `personal_yearly` | 365 天（从首次激活时起算） | 3 次 | 爱发电按年销售 |
| 终身版（保留） | `personal_lifetime` | 永久 | 3 次 | 早期用户/特殊渠道 |

> **关键设计决策**：有效期从「首次激活」时起算，而非「生成码」时起算。
> 原因：预生成的码可能在爱发电上挂几个月才卖出，如果从生成时计时，买家可能拿到一个已过期的码。

### 2.2 激活次数规则

```
total_activations = 3（每个激活码总共可激活 3 台不同设备）

同设备重装 → 不消耗次数（device_hash 匹配，直接重新签发 license）
不同设备   → 消耗 1 次次数（device_hash 不匹配，计数 +1）
3 次用完   → 激活码状态变为 exhausted，不可再激活
```

**为什么是 3 次？**
- 第 1 次：用户自己的电脑
- 第 2 次：换新电脑 / 重装系统导致指纹变化
- 第 3 次：备用电脑 / 再换一次
- 超过 3 次：明显是共享给多人，应阻止

> 同设备重装不计数是核心用户体验——用户重装 Windows 后不应被惩罚。

### 2.3 激活码状态机（简化，无 sold 状态）

```
                    批量生成
                       ↓
                   ┌──────────┐
                   │available │ ← 在爱发电卡密池中待售
                   └────┬─────┘
                        │ 用户购买后输入码激活
                        ↓
                   ┌──────────┐
             ┌─────│activated │
             │     └────┬─────┘
             │          │ 换设备激活（count < 3）
             │          ↓
             │     ┌──────────┐
             │     │activated │ ← 仍在用，count++
             │     └────┬─────┘
             │          │ count >= 3
             │          ↓
             │     ┌──────────┐
             │     │exhausted │ ← 次数用尽
             │     └──────────┘
             │
             │ 风控/退款
             ↓
        ┌──────────┐
        │ revoked  │ ← 吊销
        └──────────┘
```

> **去掉 `sold` 状态**：没有 Webhook，服务器不知道码何时被卖。码在爱发电池里是 `available`，用户激活时直接变 `activated`。如需统计「卖了但没激活」，拿爱发电订单列表跟服务器已激活列表 diff 即可。

### 2.4 签名 License Payload（不变）

```json
{
    "key_id": "XLS1-XXXX-XXXX",
    "plan": "personal_yearly",
    "device_hash": "a1b2c3...",
    "device_components": ["h1", "h2", "h3", "h4"],
    "issued_at": 1720500000,
    "expires_at": 1752036000,
    "signature": "base64url_ed25519_64bytes"
}
```

> Payload 结构完全不变，客户端零改动即可兼容。`expires_at` 由服务端在首次激活时计算并写入。

## 三、数据模型变更

### 3.1 `windows_keys` 表/对象新增字段

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `max_activations` | int | 3 | 最大激活次数 |
| `activation_count` | int | 0 | 已消耗激活次数（不同设备数） |
| `activated_at` | datetime | null | 首次激活时间（已有） |

> **去掉 `sold_at`**：没有 Webhook 来标记售出时间。

### 3.2 状态值变更

| 旧值 | 新值 | 说明 |
|------|------|------|
| `unused` | `available` | 在池中待售 |
| `used` | `activated` | 已激活，在用 |
| - | `exhausted` | 激活次数用尽 |
| `revoked` | `revoked` | 吊销（不变） |

> **去掉 `sold` 状态**：available → activated 直达。

### 3.3 `windows_migrations` 表 → 废弃

不再需要按年滚动窗口的迁移记录。激活次数直接存在 `windows_keys.activation_count` 里。
`windows_device_migrations` / `windows_migrations` 保留但不再写入新记录（向后兼容）。

### 3.4 D1 Schema 变更（Cloudflare Worker）

```sql
ALTER TABLE windows_keys ADD COLUMN max_activations INTEGER DEFAULT 3;
ALTER TABLE windows_keys ADD COLUMN activation_count INTEGER DEFAULT 0;
-- status 值域：available / activated / exhausted / revoked
-- 旧数据 'unused' → 视为 'available'，'used' → 视为 'activated'（代码层兼容映射）
```

### 3.5 JSON Store 变更（国内服务器）

`DEFAULT_STORE.windows_keys` 的每个 key 对象新增 `max_activations`, `activation_count` 字段。已有数据自动补默认值（`Object.assign` 兜底）。

## 四、服务端改动

### 4.1 批量生成 API 增强

**端点**：`POST /api/admin/generate-windows-keys`

```json
// 请求
{
    "count": 50,
    "plan": "personal_yearly",
    "max_activations": 3,
    "duration_days": 365
}
// 响应
{
    "keys": ["XLS1-A2B3-C4D5", "XLS1-E6F7-G8H9", ...],
    "count": 50,
    "plan": "personal_yearly",
    "max_activations": 3,
    "duration_days": 365
}
```

**变化**：
- 新增 `max_activations`（默认 3）
- 新增 `duration_days`（默认 365；0 = 永久）
- 生成的码状态为 `available`（不再是 `unused`）
- `expires_at` 此时**不设**——等用户激活时再算

### 4.2 激活接口改造：`issueWindowsLicense()`

**核心变化**：
1. 首次激活时设置 `expires_at`（now + duration_days）
2. 用 `activation_count` 替代迁移窗口检查
3. 同设备重装不计数
4. 新增 `EXHAUSTED` 错误码

```javascript
async function issueWindowsLicense(keyId, deviceHash, deviceName, deviceComponents) {
    const keyRow = store.windows_keys[keyId];
    if (!keyRow) return { ok: false, status: 404, body: { error: 'KEY_NOT_FOUND', message: '激活码不存在' } };

    // 兼容旧状态值
    const status = keyRow.status === 'unused' ? 'available'
                 : keyRow.status === 'used' ? 'activated'
                 : keyRow.status;

    if (status === 'revoked') return { ok: false, status: 403, body: { error: 'KEY_REVOKED', message: '激活码已被吊销' } };
    if (status === 'exhausted') return { ok: false, status: 403, body: { error: 'EXHAUSTED', message: '该激活码的激活次数已用尽（最多 3 台设备）' } };

    // 兼容旧数据
    const maxActivations = keyRow.max_activations ?? 3;
    const activationCount = keyRow.activation_count ?? 0;
    const durationDays = keyRow.duration_days ?? 365;

    const isSameDevice = keyRow.device_hash && keyRow.device_hash === deviceHash;
    const isFirstActivation = !keyRow.device_hash;

    // 检查过期（已有 expires_at 的情况）
    if (keyRow.expires_at) {
        const expiry = new Date(keyRow.expires_at);
        if (expiry < new Date()) {
            return { ok: false, status: 403, body: { error: 'SUBSCRIPTION_EXPIRED', message: '订阅已过期，请购买新的激活码' } };
        }
    }

    // 换设备检查
    if (!isSameDevice && !isFirstActivation) {
        if (activationCount >= maxActivations) {
            return { ok: false, status: 403, body: { error: 'EXHAUSTED', message: `该激活码最多激活 ${maxActivations} 台设备，已达上限` } };
        }
    }

    // 签名
    const privateKey = ensureEd25519Key();
    const now = Math.floor(Date.now() / 1000);

    // 首次激活：设置 expires_at
    let expiresAt = 0;
    if (keyRow.expires_at) {
        expiresAt = Math.floor(new Date(keyRow.expires_at).getTime() / 1000);
    } else if (keyRow.plan === 'personal_yearly') {
        const expiresDate = new Date(Date.now() + durationDays * 24 * 60 * 60 * 1000);
        expiresAt = Math.floor(expiresDate.getTime() / 1000);
        keyRow.expires_at = expiresDate.toISOString();
    }
    // personal_lifetime → expiresAt 保持 0

    const payload = {
        key_id: keyRow.key_id,
        plan: keyRow.plan,
        device_hash: deviceHash,
        device_components: deviceComponents,
        issued_at: now,
        expires_at: expiresAt,
    };
    const signature = signWindowsLicenseSync(payload, privateKey);
    const license = Object.assign({}, payload, { signature });

    // 更新设备记录
    store.windows_devices[deviceHash] = {
        device_id: deviceHash, key_id: keyId,
        device_name: deviceName || '',
        activated_at: new Date().toISOString(),
        last_seen_at: new Date().toISOString(),
        revoked: 0,
    };

    // 更新 key 记录
    const newCount = (isSameDevice || isFirstActivation) ? activationCount : activationCount + 1;
    store.windows_keys[keyId] = Object.assign({}, keyRow, {
        status: newCount >= maxActivations ? 'exhausted' : 'activated',
        device_hash: deviceHash,
        device_components: JSON.stringify(deviceComponents),
        activated_at: keyRow.activated_at || new Date().toISOString(),
        activation_count: newCount,
        max_activations: maxActivations,
        expires_at: keyRow.expires_at,
    });

    saveStoreSoon();
    return { ok: true, license, plan: keyRow.plan, expires_at: keyRow.expires_at, device_hash: deviceHash,
             activation_count: newCount, max_activations: maxActivations };
}
```

### 4.3 离线激活页面

`/offline` 页面逻辑不变（调用同一个 `issueWindowsLicense`），但响应需包含 `activation_count` 和 `expires_at`，以便页面展示给用户。

### 4.4 Webhook → 删除

**爱发电 webhook 端点 `POST /api/webhook/afdian` 整个删掉。**

不需要的原因：
- 发货：爱发电卡密池自动发货
- 验证：客户端激活时服务端 `/api/activate` 验证
- 计数/过期/设备绑定：全部在 `/api/activate` 时处理
- 售出统计：爱发电后台有订单记录，需要时 diff 即可

**好处**：
- 少一个故障点（webhook 挂了不影响发码）
- 服务器宕机也能卖（爱发电照常发货，等服务器恢复后激活）
- 不用配 `AFDIAN_*` 环境变量
- 减少攻击面

## 五、客户端改动

### 5.1 `LicenseManager` 改动

#### 5.1.1 `loadPersistedState()` — 设置 Expired 状态

```cpp
void LicenseManager::loadPersistedState()
{
    // ... 免费平台检查不变 ...

    const QString licenseText = settings.value(kTokenKey).toString();
    if (!licenseText.isEmpty()) {
        // 先解析 expires_at，判断是否过期
        QJsonParseError err;
        const QJsonDocument doc = QJsonDocument::fromJson(licenseText.toUtf8(), &err);
        if (!err.error && doc.isObject()) {
            const qint64 expiresAt = static_cast<qint64>(
                doc.object().value("expires_at").toDouble());
            if (expiresAt > 0) {
                const QDateTime expiry = QDateTime::fromSecsSinceEpoch(expiresAt);
                if (expiry <= QDateTime::currentDateTimeUtc()) {
                    setState(LicenseState::Expired);
                    return;
                }
            }
        }

        // 正常验签
        LicenseInfo info;
        if (applyLicenseFile(licenseText.toUtf8(), deviceFingerprint(), &info, nullptr)) {
            setState(LicenseState::Activated);
            return;
        }
        settings.remove(kTokenKey);
        settings.remove(kOfflineTokenKey);
    }

    // ... 试用检查不变 ...
    setState(LicenseState::Unactivated);
}
```

#### 5.1.2 新增错误码处理

在 `onActivationReply()` 中新增：
```cpp
case "EXHAUSTED":
    errorMessage = tr("该激活码的激活次数已用尽（最多 3 台设备）");
    break;
case "SUBSCRIPTION_EXPIRED":
    errorMessage = tr("该激活码已过期，请购买新的激活码");
```

### 5.2 UI 改动

#### 5.2.1 状态栏 `workspace_chrome.cpp`

| 状态 | 显示文案 | 颜色 |
|------|---------|------|
| Activated (年度) | `已激活 · 剩余 N 天` | 绿色 |

#### 5.2.2 激活对话框 `license_activation_dialog.cpp`

**在线激活成功后**：
- 显示成功消息：「激活成功！有效期至 YYYY-MM-DD」
- 如有剩余天数 < 30，显示橙色提醒

**过期状态**：
- 激活对话框自动弹出
- 顶部显示红色横幅：「您的授权已于 YYYY-MM-DD 过期，请购买新的激活码继续使用」

### 5.3 过期后的功能限制策略

采用**温和限制**（防君子不防小人）：

| 过期后行为 | 说明 |
|-----------|------|
| 仍可打开软件 | 不做硬阻断 |
| 仍可查看已导入的文件 | 只读模式 |
| 导出功能加水印 | 导出的文件标题行加「（试用过期版）」|
| 合并功能限制 | 每次最多处理 3 个文件（而非无限）|
| 顶部状态栏红字 | 「授权已过期」+ 跳转购买链接 |

## 六、分发流程（无 Webhook）

### 6.1 完整流程

```
┌──────────────────────────────────────────────────┐
│ 1. 管理员批量生成                                  │
│    工具：授权码生成器 / Admin API                  │
│    操作：生成 50 个年度版码，max_activations=3     │
│    结果：50 个 status=available 的码入库           │
└─────────────────────┬────────────────────────────┘
                      ↓
┌──────────────────────────────────────────────────┐
│ 2. 复制到爱发电                                    │
│    操作：在爱发电后台创建「自动发货」商品           │
│    将 50 个码粘贴到爱发电的「发货卡密」列表         │
│    （爱发电原生支持卡密池自动发货）                 │
└─────────────────────┬────────────────────────────┘
                      ↓
┌──────────────────────────────────────────────────┐
│ 3. 用户购买                                        │
│    用户在爱发电下单 → 支付成功                     │
│    爱发电自动从卡密池取一个码发给买家（私信/邮件）  │
│    （不经过你的服务器，服务器宕机也能发）           │
└─────────────────────┬────────────────────────────┘
                      ↓
┌──────────────────────────────────────────────────┐
│ 4. 用户激活                                        │
│    用户在软件中输入激活码 → 服务器验证             │
│    首次激活：设置 expires_at = now + 365天         │
│    绑定设备指纹 → 状态变为 activated               │
│    返回签名 license → 客户端本地验签存储           │
└──────────────────────────────────────────────────┘
```

> 四步，没有 Webhook。爱发电负责发货，服务器负责验证。各司其职，互不依赖。

### 6.2 池存量监控

在管理页面 `/xlsone/license-console`（可通过 `ADMIN_PATH` 环境变量自定义）增加：
- 显示当前 `available` 数量
- 低于 10 个时红色告警
- 一键批量补充（调 generate API）

> 没有 Webhook，服务器不知道「卖了几个」，但知道「激活了几个」。
> 如需统计销量：爱发电后台 → 订单管理，直接看。

## 七、用户体验流程

### 7.1 新用户

```
下载安装 → 14 天全功能试用 → 试用到期 → 弹出激活对话框
    ↓
点击「获取激活码」→ 跳转爱发电购买页
    ↓
支付 → 爱发电自动发码（私信/邮件）→ 输入激活码
    ↓
激活成功！显示「有效期至 2027-07-10」
```

### 7.2 续费用户（第二年）

```
软件启动 → 检测到已过期 → 显示「授权已过期」横幅
    ↓
点击「续费」→ 跳转爱发电购买页
    ↓
支付 → 获取新激活码 → 输入新码
    ↓
激活成功！新有效期至 2028-07-10
```

> 续费 = 买新码 + 激活。旧码自动失效（过期）。不需要复杂的续期逻辑。

### 7.3 换电脑

```
新电脑装软件 → 输入已有激活码 → 激活成功（消耗 1 次次数）
    ↓
显示「已激活 · 剩余 2 次换机机会」
    ↓
旧电脑的 license 在下次启动时检测到设备不匹配 → 提示重新激活
（但旧电脑的 license 文件是本地签名的，仍可离线使用直到过期）
```

### 7.4 同电脑重装

```
重装系统 → 装软件 → 输入已有激活码
    ↓
服务器检测 device_hash 匹配 → 不消耗次数
    ↓
激活成功！有效期不变（沿用原 expires_at）
```

## 九、安全考量

### 9.1 签名安全（不变）
- Ed25519 签名/验签机制不变
- 私钥仅存服务器环境变量
- 客户端只内嵌公钥
- License 文件本地验签，无法伪造

### 9.2 池安全
- 激活码生成使用密码学随机数（已有）
- 码格式 `XLS1-XXXX-XXXX`，32^8 ≈ 1 万亿种组合，暴力枚举不可行
- 激活接口有限流（10次/分钟/IP）

### 9.3 过期绕过
- 客户端检查 `expires_at` 时用 `QDateTime::currentDateTimeUtc()`
- 用户改系统时间可绕过（防君子不防小人）
- 服务端在重新激活时也会检查 `expires_at`

## 附录 A：爱发电卡密池配置说明

1. 登录爱发电 → 管理后台 → 商品管理
2. 创建/编辑商品 → 开启「自动发货」
3. 在「发货方式」选择「卡密」
4. 将批量生成的激活码（每行一个）粘贴到卡密列表
5. 设置「购买后自动发货」
6. 用户购买后，爱发电自动从列表取一个码通过私信发给买家

> **不需要配置 Webhook**。爱发电独立完成发货，你的服务器只负责激活验证。

## 附录 B：完整激活码生命周期

```
生成 ──→ available ──→ activated ──→ exhausted
  │         │              │              │
  │    在池中待售       用户激活       3台设备用完
  │         │              │
  │         │              ├──→ 过期 → 用户买新码
  │         │              │
  │         │              └──→ 换设备（count < 3）→ activated
  │         │
  │         └──→ 管理员删除 → revoked
  │
  └──→ 管理员生成后直接吊销 → revoked
```
