Excel 合并计算、Power Query、VBA 与专用工具，应该怎么选？

没有一种方法适合所有表格。关键不是“哪个更高级”，而是源数据是明细清单还是固定模板、任务是否重复、是否需要保留版式和追溯来源。

结论先行

方法最适合主要优势主要限制
合并计算少量同布局表的总和、平均、计数Excel 内置、上手快引用多时维护繁琐，追溯有限
Power Query追加明细、清洗字段、定期刷新步骤可保存，适合重复流程固定版式和复杂布局需额外转换
VBA规则明确且需要深度定制自动化自由度高需要编写、测试和维护代码
表表归一多份同模板报表按位置汇总保留布局、来源可追溯、离线不适合结构完全不同的文件

Excel 合并计算：一次性按位置汇总

Microsoft 将“合并计算”用于从多个工作表汇总总和、平均、计数等结果，并区分按位置和按标签合并。它适合结构规整、文件数量不多的任务。

  • 选它：你已经在 Excel 中，源区域少，结果只需基础汇总函数。
  • 别选它：每月要添加很多新文件，或必须逐格解释每个数字来自哪里。

参考：Microsoft 支持：合并多个工作表的数据。

Power Query：重复清洗和追加明细

Power Query 可以从工作簿、文件夹等来源导入数据，记录清洗与转换步骤，再刷新结果。对于字段一致的明细清单，它通常比手动复制可靠。

  • 选它：每月收到相同列结构的流水、订单、人员明细，需要清洗后追加。
  • 别选它：源文件是带说明、合并单元格和固定版式的上报模板，而你希望保留原布局。

参考：Microsoft 支持：合并查询和联接表。

VBA：规则稳定、团队能维护代码

VBA 可以按业务规则遍历文件、读取范围、写入结果和生成日志。它的优势是定制，成本则是代码需要持续测试，模板变化时也要修改。

  • 选它：流程高度固定、有明确异常处理、团队有人负责维护。
  • 别选它：使用者无法审查宏，或安全策略禁止运行未知宏。

表表归一：固定模板报表的离线汇总

表表归一把“按相同位置聚合”和“穿透查看来源”做成桌面交互流程。它不要求写公式、查询或宏，适合业务人员反复处理统一模板。

  • 选它：分公司、部门、乡镇或项目使用同一模板上报，需要合计并复核。
  • 别选它：文件字段完全不同，或目标是构建长期数据仓库和复杂关联模型。

按五个问题做决定

  1. 你要“追加明细行”，还是“保持模板按位置合计”？
  2. 这是一次性任务，还是每周/月重复？
  3. 源文件的表头、行列和模板版本是否一致？
  4. 结果出错时，是否必须追溯到具体源文件？
  5. 团队是否有时间维护查询或代码？
实际工作可以组合方法先用 Power Query 清洗明细，再用数据透视表分析；或先统一模板，再用表表归一按位置汇总。工具选择应服从数据结构。
